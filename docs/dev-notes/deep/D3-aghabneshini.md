# D3 قانون‌نامه‌ی تلاش

حکم: **قوی**  ·  دسته‌ی وابستگی: **درز و مبدل**  ·  پیش‌نیاز: پیش‌نیازِ سخت: هیچ. تابع خالص است و امروز هر دو فراخوان در دست‌اند. ولی ترتیبِ درست این است که این واحد پیش از هر کاری روی batch.m برود، چون هر تغییری در حکمِ دسته‌ای بی این قانون‌نامه یعنی نوشتنِ نسخه‌ی سومِ همان تصمیم. و واحدِ بعدی بر شانه‌ی همین می‌نشیند: برداشتنِ NULL در batch.m:140، که تنها بعد از وجودِ ZJudgeTry یک خط است.

> این سند طرح است، نه کدِ نوشته‌شده. روی ویندوز و بی کامپایلر نوشته شد، پس
> هیچ ادعایی درباره‌ی «رفتار عوض نشد» ندارد. آن را فقط اجرا روی مک ثابت می‌کند.

## تصمیمِ گیرافتاده

تصمیمِ گیرافتاده یکی است: «این تلاش چه شد و بعدش چه کنیم». هر بار که یک تکه از شبکه برمی‌گردد، باید حکم شود متن کافی است، یا سرور شنید و حرفی نبود، یا باید دوباره رفت و چقدر صبر. امروز این حکم دو جا و دو شکل نوشته شده: در queue.m خط ۳۰۴ تا ۳۳۶ لای قفل و لاگ و دفترچه، و در batch.m خط ۱۰۵ تا ۱۳۳ لای حلقه‌ی تلاش و مکث و آمار. دو نسخه واگرا شده‌اند و یک واگرایی‌شان اتفاقی است: مسیر دسته‌ای دلیلِ بسته شدنِ خط را NULL می‌دهد، پس همان تفکیکی که باگِ ۲۰۲۶-۰۸-۱۹ را در مسیر زنده بست، در مسیر دسته‌ای هنوز وجود ندارد.

## آزمونِ حذف

ZJudgeTry را بردار. پیچیدگی محو نمی‌شود، در دو فراخوان دوباره ظاهر می‌شود: queue.m خط ۳۰۴ تا ۳۳۶ و batch.m خط ۱۰۵ تا ۱۳۳. همین حالا هم دقیقا همان دو جا ظاهر شده و واگرا شده؛ یعنی آزمونِ حذف را نه با تصور، با تاریخِ ریپو جواب می‌دهیم. و یک نتیجه‌ی سنجیده‌شده‌ی حذف در دست است: کامیت f98e42f دلیلِ بسته شدن را برگرداند، queue.m از آن استفاده کرد و batch.m همان‌جا NULL گرفت. با یک قانون‌نامه، آن NULL یک خط بود نه یک نسخه‌ی جاافتاده.

## رابطِ پیشنهادی

```objc
// ---------- قانون‌نامه‌ی تلاش (app/Sources-objc/try.m) ---------- [آینده]
// یک حکم برای یک تلاش، مشترکِ زنده و دسته‌ای. تفاوتِ واقعیِ دو مسیر زمان‌بندی است
// (زنده: کاربر منتظر است؛ دسته‌ای: کسی منتظر نیست)، پس زمان‌بندی از بیرون تزریق
// می‌شود و قاعده یکی می‌ماند.

typedef NS_ENUM(NSInteger, ZTryVerdict) {
    ZTryTake,     // متن کافی است، تکه تمام
    ZTrySilent,   // شنید و حرفی نبود، تکه تمام، سهمش در متن هیچ
    ZTryAgain,    // دوباره، بعد از waitSec
    ZTryStop,     // دیگر برنمی‌گردد: صدا نیست، یا سقفِ تلاش
};

// زمان‌بندی. هر ستون یک اندازه‌گیریِ ثبت‌شده دارد، پس ستون است نه چیزی که پاک شود.
typedef struct {
    NSInteger maxTries;   // ۰ = بی‌سقف (زنده)، ۳ (دسته‌ای)
    BOOL freeRetry;       // یک تلاشِ اضافه‌ی بی‌مکث، یک بار در عمرِ تکه (زنده، ~۱۳٪)
    BOOL napBetween;      // مکثِ ۴×تلاش جای ساعتِ مشترکِ صف (دسته‌ای)
    BOOL thinIsAgain;     // متنِ کم‌حرف تلاشِ دوباره می‌خواهد (دسته‌ای)
    BOOL streakCools;     // لالیِ پیاپی عقب می‌کشد (دسته‌ای، ۸۸٪ به ۶۰٪)
} ZTryClock;
extern const ZTryClock kZClockLive, kZClockBatch;   // دو مبدلِ این درز

// حالِ تکه سرِ این تلاش. همه اسکالر، پس تابع خالص می‌ماند.
typedef struct {
    NSInteger tries;         // شاملِ همین تلاش
    NSInteger step;          // پله‌ی عقب‌نشینیِ مشترکِ صف
    NSInteger deafStreak;    // تکه‌های پیاپی که لال برگشتند
    NSUInteger words;        // کلمه‌های بهترین متنِ تا الان؛ ۰ یعنی خالی
    NSUInteger prevWords;    // NSNotFound یعنی تلاشِ اول
    double sec;              // طول صدای این تکه
    BOOL hasAudio, voiced, askedFree, disposable;
} ZTry;

typedef struct {
    ZTryVerdict verdict;
    NSTimeInterval waitSec;
    NSInteger step, deafStreak;   // حالِ تازه، همان‌جا برمی‌گردد
} ZTryPlan;

// خالص: نه ساعت می‌خواند، نه شبکه، نه ZLog، نه قفل.
// `why` نال یعنی نمی‌دانیم خط چرا بسته شد؛ آن‌وقت ZTrySilent هرگز درنمی‌آید.
ZTryPlan ZJudgeTry(ZTry t, NSString *why, ZTryClock c);

NSTimeInterval ZBackoffDelay(NSInteger step);   // از queue.m به همین‌جا کوچ می‌کند
```

## پشتِ درز

پشتِ درز هر چیزی می‌ماند که تصمیم نیست: صدا زدنِ ZTranscribeSegment، قفلِ صف، نوشتنِ دفترچه، ZLog، خواندنِ ساعت و خوابیدن (nap و dispatch_after)، و موازی‌سازیِ jobs. درز دقیقا دو مبدل دارد و همان دو تا دلیلِ وجودش‌اند: kZClockLive که queue.m سرِ pump به کار می‌برد، و kZClockBatch که batch.m سرِ runPiece. یک مبدل بود، درز فرضی می‌شد؛ دو مبدلِ واقعی با دو زمان‌بندیِ اندازه‌گیری‌شده یعنی درز واقعی است.

## تستِ طلایی

فایل: `tools/try_test.sh` [آینده]

کامپایل: clang -fobjc-arc -O1 -Wall -Werror -I app/Sources-objc app/Sources-objc/try.m tools/try_test.m -framework Foundation. فقط همین دو فایل و فقط Foundation، مثل tools/seg_test.sh خط ۸. اگر این خط کامپایل نشد، یعنی تصمیم واقعا بیرون نیامده و ورودی‌خروجی با خودش آمده. [آینده]

**توجه:** `tools/release.sh` از کامیت `a47d1ba` با گلابِ `tools/*_test.sh` تست‌ها را پیدا می‌کند، پس اسمِ تستِ تازه دستی به آن اضافه نمی‌شود. ساختنِ فایل با پسوندِ `_test.sh` کافی است.

چرا این تست ادعا را ثابت می‌کند: چون هر ردیف یک تصمیمِ واقعیِ امروز است با مکانش در سورس، و kZClockLive و kZClockBatch همان دو ثابتی هستند که در محصول به کار می‌روند، نه دو ثابتِ تست. سه ردیف مستقیم از خرابیِ واقعیِ گیت می‌آیند (00ef46e، «با git log -S روی prevWords پیدایش کن، هش قبلی غلط بود»، f98e42f). و گاردِ ادای تست جای دیگری است: tools/queue_test.sh و app/build.sh باید بی‌تغییر سبز بمانند، پس فراخوان‌ها واقعا از این تابع می‌گذرند و صف همان رفتارِ قبل را دارد.

## ریسک‌ها

- رفتارِ عوض‌شده در همین واحد: هیچ‌کدام از حکم‌های کاربردیدنی. تنها چیزی که قرمز می‌شود tools/queue_test.m:560 است که روی متنِ سورس ادعا می‌کند («ZCloseWasClean(why)» در queue.m). حق دارد قرمز شود و باید به مکانِ تازه اشاره کند، ولی این تغییرِ متنِ تست است نه تغییرِ رفتار. اگر جز این ردیف چیزی قرمز شد، واحد غلط اجرا شده.
- خطرِ اصلی همین است که ستونِ اندازه‌گیری‌شده به بهانه‌ی «یکی کردن» پاک شود. سه ستون دلیلِ سنجیده دارند و باید بمانند: freeRetry (زنده، ~۱۳٪ خالی‌ها)، streakCools (دسته‌ای، ۸۸٪ به ۶۰٪ بعد از ~۴۰۰ سشن)، thinIsAgain با شرطِ «همان تعداد کلمه» (۳۰ ثانیه از ۸۱ روی وویس شش دقیقه‌ای). هیچ‌کدام روشن یا خاموشِ هر دو مسیر نمی‌شود مگر با یک اندازه‌گیریِ تازه.
- پلامبِ دلیل در مسیر دسته‌ای (batch.m:140، برداشتنِ NULL) وسوسه‌کننده است ولی رفتار را عوض می‌کند: پاره‌ای که با دلیلِ تمیز خالی برگشته امروز تا سه بار می‌رود و در آمارِ لالی می‌آید، بعدش یک بار می‌رود و «حرفی نبود» می‌شود. این واحدِ بعدی است، با اندازه‌گیریِ خودش روی ضبط ۰۱، نه اینجا.
- کارِ همزمان: در مسیر دسته‌ای runPiece روی چند نخ می‌دود و deafStreak زیر _stateLock است. ZJudgeTry خالص است و خودش قفل ندارد، پس فراخوان باید خواندنِ deafStreak و نوشتنِ مقدارِ برگشتی را در یک قفل بگذارد. اگر این جا بیفتد، عقب‌کشیدن بی‌صدا خراب می‌شود و هیچ تستی نمی‌گیردش.

## اندازه‌ی تخمینی

افزوده حدود 380 خط، برداشته حدود 85 خط. مبنا: سنجیده با wc -l و grep -n روی همین ریپو: try.m تازه ~۱۰۰ خط (سرآیندِ توضیحی مثل بالای queue.m، به‌اضافه‌ی کوچِ ZBackoffDelay از queue.m:25)، zemzeme.h حدود ۳۵ خط رابط، فراخوان‌های تازه ~۴۰ خط، و تست ~۲۰۵ خط (tools/queue_test.m ۵۷۰+ خط است، tools/seg_test.sh دوازده خط). حذف: queue.m خط ۳۰۴ تا ۳۳۶ منهای بخشِ لاگ و قفل (~۳۵ خط)، batch.m خط ۷۴ تا ۹۱ و ۱۰۵ تا ۱۳۳ منهای بخشِ nap و ZLog (~۵۰ خط). دفتر دست نمی‌خورد: queue.m ۵۳۳ و batch.m ۵۶۱ خط‌اند، هر دو زیر سقفِ ۷۰۰ و هیچ‌کدام در PINS نیستند، پس بندِ جابه‌جاییِ tools/ledger_test.sh بی‌اثر است. app/build.sh هم با Sources-objc/*.m گلاب می‌گیرد (خط ۳۰) و tools/release.sh با tools/*_test.sh (خط ۵۹)، پس فایل و تستِ تازه خودشان ثبت می‌شوند و هیچ‌کدام از این دو دست نمی‌خورد.
