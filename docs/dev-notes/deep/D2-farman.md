# D2 جدول فرمان‌ها

حکم: **قوی**  ·  دسته‌ی وابستگی: **درز و مبدل**  ·  پیش‌نیاز: هیچ. این واحد پیش‌نیاز ندارد و باید اول برود، چون بزرگ‌ترین برداشت خط از app.m و panel.m از همین درمی‌آید و واحدهای بعدی روی نسخه‌ی کوچک‌شده‌ی آن دو کار می‌کنند.

> این سند طرح است، نه کدِ نوشته‌شده. روی ویندوز و بی کامپایلر نوشته شد، پس
> هیچ ادعایی درباره‌ی «رفتار عوض نشد» ندارد. آن را فقط اجرا روی مک ثابت می‌کند.

## تصمیمِ گیرافتاده

تصمیمِ گیرافتاده این است: کدام فرمان‌ها وجود دارند، هر کدام چه کلید و چه برچسب و چه نمادی دارد، و کدامشان بی‌سشن هم کار می‌کند. این تصمیم امروز هفت جا تکرار شده و هیچ‌کدام واحد حقیقت نیست. دامنه‌ی هر فرمان تنها در actionForCode: زندگی می‌کند، برچسبش در menuNeedsUpdate:، کی‌کپش در panel.m و cheatsheet.m، و دوباره در دو ریدمی. ورودی‌خروجی هر فرمان (تپ CGEvent، NSMenuItem، NSButton، کشیدن کارت) با همین تصمیم قاطی است، پس عوض کردن یک فرمان یعنی دست زدن به هفت جا.

## آزمونِ حذف

جدول را بردار. آن‌وقت دامنه‌ی «هر وقت» باید در actionForCode: و در menuNeedsUpdate: و در دو ریدمی جدا نوشته شود، کی‌کپ در panel.m و cheatsheet.m و دو ریدمی، و برچسب در سه جا. یعنی همان پانزده ردیف در هفت فراخوان دوباره ظاهر می‌شود. پیچیدگی محو نمی‌شود، برمی‌گردد. پس داشت کار می‌کرد. در مقابل، آزمون حذف روی یک بلاک تنها (مثلا onSecondPass) پیچیدگی را جابه‌جا می‌کند نه محو، و همین می‌گوید بلاک‌ها قسمت کم‌عمق‌اند.

## رابطِ پیشنهادی

```objc
// zemzeme.h، جای ۳۲ پراپرتی بلاک قبلی

typedef NS_ENUM(uint8_t, ZCmd) {
    ZCmdEnd, ZCmdPause, ZCmdCopy, ZCmdInsert, ZCmdTrash,
    ZCmdLang, ZCmdMode, ZCmdFile, ZCmdHistory, ZCmdHelp,
    ZCmdSens, ZCmdSecond, ZCmdPreview, ZCmdAI, ZCmdSign,
};

typedef struct {
    ZCmd        cmd;
    int16_t     code;      // کیکد Carbon؛ -۱ یعنی کلید ندارد
    const char *cap;       // کی‌کپ: "C"، "Space"، "esc"
    const char *label;     // برچسب کوتاه فارسی، UTF-8
    const char *sel;       // متد روی ZAppDelegate
    const char *symbol;    // SF Symbol، حالت خاموش
    const char *symbolOn;  // نال یعنی همان symbol
    const char *setting;   // نام تنظیم اگر تاگل است، وگرنه نال
    BOOL        anytime;   // بی‌سشن هم کار می‌کند
    int8_t      group;     // دسته: ۰ کارهای سشن، ۱ ابزارها، ۲ تاگل‌ها
} ZCmdRow;

const ZCmdRow *ZCmdTable(size_t *n);                      // به ترتیب نوار
const ZCmdRow *ZCmdOf(ZCmd c);
const ZCmdRow *ZCmdForKey(int16_t code, BOOL inSession);  // نال یعنی مال ما نیست

// ZHotkeyTap و ZPanel هر دو، جای ۱۷ و ۱۵ بلاک:
@property (nonatomic, copy) void (^onCommand)(ZCmd c);
// این دو می‌مانند، چون واقعا فرمان جدولی نیستند:
@property (nonatomic, copy) void (^onToggle)(void);   // دابل‌تپ، کلید حرفی ندارد
@property (nonatomic, copy) BOOL (^onEscape)(void);   // هم‌زمان، جواب BOOL، اولویت‌دار
```

## پشتِ درز

پشت درز، ورودی‌خروجی هر چهار نما می‌ماند: ساختن CGEventTap و بلعیدن رویداد در inject.m، ساختن NSMenuItem و تیک و تولتیپ در app.m، ساختن NSButton و کی‌کپ و رنگ در panel.m، و کشیدن ردیف‌های کارت در cheatsheet.m. جدول هیچ‌کدام را نمی‌داند و هیچ فریم‌ورک UI را باز نمی‌کند. درز واقعی است، نه فرضی: دو مبدل به بالا دارد (ZHotkeyTap.onCommand و ZPanel.onCommand) و چهار مصرف‌کننده‌ی خواندنی به پایین، به علاوه‌ی دو ریدمی که با گارد به جدول بسته می‌شوند نه با کد. تولتیپ‌های بلند و حالت‌دار عمدا پشت درز می‌مانند.

## ریسک‌ها

- ورودی‌خروجی گیر: سلکتور رشته‌ای شد، پس کامپایلر دیگر غلط املایی sel را نمی‌گیرد. بی ردیف ب۵ این واحد نباید مرج شود.
- تفاوت واقعی گم شود: onEscape جواب BOOL می‌دهد و هم‌زمان صدا زده می‌شود، و onToggle کلید حرفی ندارد. هر دو بیرون جدول می‌مانند. بردنشان به onCommand تصمیم بلعیدن را تاخیر می‌اندازد و Esc را از vim می‌دزدد.
- مالکیت سیم‌کشی عوض می‌شود: امروز session.m در wirePanel هشت بلاک را می‌بندد و در unwirePanel نیل می‌کند (خط ۱۵۳ تا ۱۷۹). با یک onCommand مالک باید app.m باشد و فرمان‌های سشنی از sessionDo بروند، که خط ۵۰۲ بی‌سشن خودش برمی‌گردد. رفتار یکی است ولی گارد «دکمه‌ی سشن مرده» از نیل بودن بلاک به نبودن _session منتقل می‌شود.
- تولتیپ‌ها وسوسه‌اند: بیست و چند تولتیپ حالت‌دار در app.m و panel.m با hasKey و keyLocked و mode عوض می‌شوند. اگر به جدول بیایند، جدول هم‌اندازه‌ی پیاده‌سازی می‌شود و این واحد به همان جابه‌جایی خط تبدیل می‌شود که خط سرخ منعش کرده.
