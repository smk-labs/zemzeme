# D6 زمانِ اثرِ تنظیم، سر شروع سشن

حکم: **ارزش بررسی**  ·  دسته‌ی وابستگی: **درون‌پروسه**  ·  پیش‌نیاز: هیچ. مستقل است. فقط اگر واحدی سراغ صف یا دفترچه‌اش می‌رود، این یکی باید جلوتر بنشیند، چون ردیفِ زبانِ دفترچه را همین عوض می‌کند.

> این سند طرح است، نه کدِ نوشته‌شده. روی ویندوز و بی کامپایلر نوشته شد، پس
> هیچ ادعایی درباره‌ی «رفتار عوض نشد» ندارد. آن را فقط اجرا روی مک ثابت می‌کند.

## تصمیمِ گیرافتاده

تصمیمی که لای ورودی‌خروجی گیر افتاده «قفل» یا «زنده» نیست، «کِی» است. session.m سیزده بار ZSettings.shared را می‌خواند و برای هر خواندن یک جوابِ نانوشته دارد: mode سر شروع در _mode می‌نشیند، lang شش بار از یک گلوبالِ متغیر خوانده می‌شود، recordSessions سر تحویل، insertMode سر درج. همین عدمِ تقارن خودِ نقص است، نه زنده‌بودن. و جایی که عدمِ تقارن به خرابی رسیده پیداست: زبان سر session.m:101 در صف قفل می‌شود و switchLang آن را عوض نمی‌کند، پس سشنی که فارسی شروع شده و انگلیسی تمام می‌شود در دفترچه fa ثبت می‌کند و بازیابی بعد از کرش تکه‌های بی‌زبان را fa برمی‌گرداند. پس نامزدِ «عکس گرفتن از همه‌ی تنظیمات» غلط است و به جایش تصمیمِ زمان باید به شکل تابع خالص بیرون بیاید و سشن فقط دو فیلد داشته باشد: _mode قفل، و _lang زنده با یک نویسنده.

## آزمونِ حذف

برداریمش، پیچیدگی جابه‌جا می‌شود نه محو. دانشِ «کدام تنظیم از کِی» در سیزده خواندنِ session.m و در engine.m:147 و audio.m:278 و queue.m:490 و core.m:384 دوباره ظاهر می‌شود، هر بار به شکل یک کامنت یا هیچ. شاهدش خودِ ریپوست: کامنتِ zemzeme.h:949 می‌گوید زبان از سشن بعد اثر می‌کند و README:120 می‌گوید همان لحظه، و هر دو ماندند چون هیچ‌جا این تصمیم یک نام نداشت. پس داشت کار می‌کند.

## رابطِ پیشنهادی

```objc
// ---------- زمانِ اثرِ تنظیم ----------
// از کِی اثر می‌گیرد. تابعِ خالص و در هدر، کنارِ ZSettings، به همان دلیلِ
// ZChooseWritePath: قرارداد کنار خودش بنشیند و بی هیچ لینکی آزمودنی باشد.
typedef NS_ENUM(NSInteger, ZWhen) {
    ZWhenFrozen = 0,  // سر شروعِ سشن قفل. عوض شدنش تا سشنِ بعد اثری ندارد
    ZWhenRound,       // از دورِ بعدیِ شنیدن
    ZWhenNow,         // همان لحظه، وسطِ همین دور
    ZWhenExit,        // لحظه‌ی تحویل، یا نوشتن روی دیسک
};

typedef NS_ENUM(NSInteger, ZSettingKey) {
    ZKeyMode = 0, ZKeyLang, ZKeyPreviewStream, ZKeyFinalPass, ZKeySecondPass,
    ZKeyHighSens, ZKeyRecordSessions, ZKeyInsertMode, ZKeyTypeDelay,
    ZKeySignature, ZKeySounds, ZKeyUpstreamFLAC,
    ZKeyCount,
};

// یک switch و بس. بی default، تا افزودنِ کلیدِ تازه بی‌زمان کامپایل نشود.
static inline ZWhen ZSettingWhen(ZSettingKey k);

// و در ZSession، تنها دو فیلدِ تنظیمی:
//   ZMode      _mode;   // ZWhenFrozen، از قبل هست. همین الگو
//   NSString  *_lang;   // ZWhenNow با یک نویسنده: switchLang
// هرچه ZWhenNow یا ZWhenRound یا ZWhenExit است سر جایش زنده می‌ماند.
```

## پشتِ درز

پشت درز، خودِ منبعِ تنظیم می‌ماند: ZSettings.shared و NSUserDefaults و کشِ اتمیکِ نخ صدا. تصمیمِ زمان می‌آید بیرون به شکل ZSettingWhen و آنچه سشن نگه می‌دارد دو فیلد است. دو مبدل دارد، پس درز واقعی است نه فرضی: مبدل اول ZSettings واقعی روی دیسک، مبدل دوم تنظیمِ درون‌حافظه‌ای در tools/snap_test.m که وسطِ آزمون یک مقدار را عوض می‌کند تا اثبات شود قفل قفل مانده و زنده حرکت کرده. مبدلِ سوم از قبل موجود است: tools/insert_test.m همین حالا ZSettings.shared را با آرگومان خط فرمان می‌سازد. [آینده]

## تستِ طلایی

فایل: `tools/snap_test.sh` [آینده]

کامپایل: clang -fobjc-arc -O1 -Wall -Werror -Wswitch-enum -I app/Sources-objc tools/snap_test.m -framework Foundation -o "$out". core.m به‌علاوه Foundation و AppKit و CoreText، چون ZSettingWhen یک static inline در هدر است و هیچ لینکی لازم ندارد، دقیقا مثل ZChooseWritePath در insert_test. بخش دوم اسکریپت هیچ کامپایلی ندارد و گاردِ گرپ روی session.m است. [آینده]

**توجه:** `tools/release.sh` از کامیت `a47d1ba` با گلابِ `tools/*_test.sh` تست‌ها را پیدا می‌کند، پس اسمِ تستِ تازه دستی به آن اضافه نمی‌شود. ساختنِ فایل با پسوندِ `_test.sh` کافی است.

چرا این تست ادعا را ثابت می‌کند: چون ادعا دو تکه است و هر تکه سنجه‌ی خودش را دارد. تکه‌ی اول «هر تنظیم یک زمانِ نوشته‌شده دارد» است و جدولِ ردیف‌به‌ردیف با ارجاع به README و کد، ادای اثبات نیست: هر ردیف امروز از یک خطِ مشخص خوانده می‌شود و اگر فردا کسی جای خواندن را عوض کند و زمان را نه، ردیف قرمز می‌شود. تکه‌ی دوم «سشن دیگر خودش نمی‌خواند» است و آن را تست واحد نمی‌گیرد، چون session.m بی AppKit و پنل و موتور کامپایل نمی‌شود؛ پس گاردِ گرپ می‌گیردش، همان‌طور که insert_test.sh نگهبانِ استثنای per-app است. و ردیفِ دفترچه، تنها ردیفی است که امروز قرمز است و باید باشد: یک خرابیِ واقعیِ سنجیده، نه فرض.

### ردیف‌های جدول

1. ZSettingWhen(ZKeyMode) == ZWhenFrozen. سند: session.m:72 آن را در _mode می‌ریزد و toggleMode در session.m:697 هر دو را با هم عوض می‌کند.
2. ZSettingWhen(ZKeyLang) == ZWhenNow. سند: README:120 و README:369 و engine.m:171. کامیت d6896bb همان خرابی است: قبلش switchLang فقط تنظیم را می‌نوشت و موتور تا آخر به زبان قبلی می‌نوشت.
3. ZSettingWhen(ZKeySecondPass) == ZWhenRound. سند: README:403 «از دور بعدیِ شنیدن» و engine.m:147 که سر ساختِ موتور خوانده می‌شود.
4. ZSettingWhen(ZKeyHighSens) == ZWhenNow. سند: core.m:275 که ستر همان‌جا کشِ اتمیک را می‌نویسد. پس فرضِ «حساسیت از دور بعد اثر می‌کند» غلط است و README هیچ‌جا آن را نگفته.
5. ZSettingWhen(ZKeyRecordSessions) == ZWhenExit. سند: session.m:562 و کامنتِ queue.m:483 تا ۴۹۰ که صریح می‌گوید حالِ همین حالا خوانده شود.
6. ZSettingWhen(ZKeyFinalPass) == ZWhenNow. سند: app.m:285 و app.m:1046 و app.m:1094 از بیرونِ سشن خاموشش می‌کنند. قفل کردنش حالتِ «روشن و بی‌کلید» را برمی‌گرداند.
7. ZSettingWhen(ZKeyInsertMode) == ZWhenExit و ZSettingWhen(ZKeyTypeDelay) == ZWhenExit. سند: session.m:527 و ۵۲۹، خواندن در همان لحظه‌ی کارِ کاربر.
8. ZSettingWhen(ZKeySignature) == ZWhenExit. سند: core.m:384 و README:203 که می‌گوید خاموش کردن، تاریخچه را از همان لحظه بی‌امضا می‌کند.
9. ZSettingWhen(ZKeyPreviewStream) و ZSettingWhen(ZKeySounds) و ZSettingWhen(ZKeyUpstreamFLAC) همه ZWhenNow. سند: session.m:220 و engine.m:231 و core.m:153 و stream.m:79، هر چهار سر مصرف خوانده می‌شوند.
10. هیچ کلیدی بی زمان نماند: حلقه روی ۰ تا ZKeyCount، هر جواب باید یکی از چهار مقدار باشد. و switch بی default است، پس -Wswitch-enum کلیدِ تازه‌ی بی‌زمان را سر کامپایل قرمز می‌کند.
11. گاردِ گرپ: در session.m هیچ خواندنِ ZSettings.shared جز mode سر شروع نماند. معیار: grep 'ZSettings.shared' منهای سه سترِ خط ۶۹۹ و ۷۱۸ و ۷۳۲ فقط یک خط بدهد. امروز ۱۳ خط می‌دهد.
12. خرابیِ واقعیِ زبان: سشنی که فارسی شروع شده و وسطش انگلیسی شده باید en در دفترچه بنشیند. امروز fa می‌نشیند، چون session.m:101 قفل است و switchLang آن را عوض نمی‌کند. کامیت 89678ba همان‌جاست که این فیلد آمد و switchLang از قبل وجود داشت.
13. بازیابی بعد از کرشِ همان سشن: تکه‌ی بی‌زبان روی مسیر queue.m:444 باید en برگردد نه fa.
14. رفتار عوض نشود: خروجیِ measure.m با --switchlang، همان دو اجرای پیش و پس از تغییر، باید بایت‌به‌بایت یکی باشد.

## ریسک‌ها

- ریسکِ اصلی: اگر کسی این واحد را «عکس از همه‌ی تنظیمات» بفهمد، خطِ سرخ می‌شکند. قفل کردنِ lang رفتارِ README:120 را عوض می‌کند، قفل کردنِ finalPassEnabled خاموش‌شدنِ خودکارِ app.m:1046 را بی‌اثر می‌کند، و قفل کردنِ recordSessions مستقیم برخلافِ کامنتِ queue.m:483 است. در عکس فقط mode می‌نشیند، که از session.m:72 آنجا هست.
- ردیفِ دفترچه‌ی زبان یک تغییرِ رفتار است، هرچند اصلاحِ باگ. متنِ روی دیسکِ سشن‌های موجود عوض نمی‌شود، ولی دفترچه‌ی نیمه‌کاره‌ای که با نسخه‌ی قبل نوشته شده lang قدیمی دارد. بازیابی همان مسیرِ فالبک را می‌رود، پس بی‌خطر است، ولی باید صریح گفته شود نه کشف شود.
- گاردِ گرپ به شماره‌ی خط تکیه نکند. اگر به عددِ ثابتِ ۴ بسته شود، افزودنِ یک نوشتنِ مشروعِ تازه بی‌دلیل قرمز می‌کند. معیار باید «هیچ خواندنی جز mode» باشد، نه یک عددِ کل.
- ZSettingKey یک شمارشِ موازیِ پراپرتی‌هاست و می‌تواند از ZSettings عقب بیفتد. -Wswitch-enum کلیدِ اضافه‌شده به شمارش را می‌گیرد، ولی پراپرتیِ تازه‌ای که به شمارش اضافه نشود را نمی‌گیرد. این حفره باید نوشته شود، وگرنه بعدا کشف می‌شود.
